# YANCE V2 domain CI — actual scope, no false green

The runner executes `scripts/ci/verify-frozen-contracts.cjs` on **every PR** (same frozen historical evidence hashes/IDs as bootstrap but deliberately drops obsolete P3-0 application-directory-must-be-empty policy) (252 stable IDs, 100 UIE and frozen hashes). `run-checks.mjs native` discovers checked-in `*.test.mjs` under all real source domains and runs them. If native source exists without tests, the gate fails. `agno-python-native` installs only the pinned official Agno development test requirements and runs pytest if the Agno files exist. `synthetic-m0-contract` runs native checked-in M0 tests if present, and prints **NOT_APPLICABLE** otherwise. This is not an actual provider business chain.

If the B+C isolated frontend exists, the workflow runs a fresh npm ci, TypeScript, Vite, source vendor SHA checks, npm audit, and a new Playwright Chromium DOM smoke with screenshots in the artifact. **Do not use `npm test` old W39**, because it expects an ignored `test-output/W39_CHROME_UAT_RESULTS.json` absent from a clean checkout; don't fake history by copying the file. W46 should replace that self-test with a checked-in deterministic test suite as an independently reviewed source delta.

Jobs are read-only on GitHub-hosted Linux, no credentials or social accounts. Windows WebView2, real IME/DPI, native Tauri Toast and human UX still need isolated Windows testing with exact SHA, not use the real logged-in desktop as a public PR runner. The browser job is a synthetic smoke test, not independent W40/41/42 signoff.

Existing 14 Draft PRs can be audited **without editing their source worktrees** using the workflow's `workflow_dispatch` on default main with three inputs: `target_sha` (existing PR's exact 40-character source head), `target_base_sha` (actual PR base commit), and `target_pr` (report metadata). Every job checks out exactly `target_sha`; report JSON derives the SHA from the actual checked out Git object, not the default branch workflow event SHA. These manual-dispatch runs are independent audit evidence, **not PR-head required status checks** until GitHub associates a real pull_request run with that head. GitHub main PR checks run automatically on subsequent opened/synchronized/ready-for-review events. Do not create empty commits or alter owner source for status cosmetics.

Mandatory check name after actual green run: `nonproduction-merge-gate`. Only set this as required main rule after it genuinely exists and succeeds on the remote runner. No blanket auto-merge and no magic owner approvals.
