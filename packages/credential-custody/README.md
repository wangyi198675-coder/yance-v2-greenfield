# W55 Credential Custody — nonproduction and sealed

**SAFETY STATUS:** The normal `Vault::new()` is permanently sealed. It cannot store, inspect, rotate, revoke, or lease credentials. Only `#[cfg(test)]` unit tests can instantiate an unsealed vault with synthetic disposable bytes. There is deliberately no public unseal function or user/HTTP/JS credential API. Nothing here connects to social channels or replaces W24/W44 identity/consent/grant/epoch authority or W25 delivery.

Windows-native backend: generic Windows Credential Manager (`CredReadW`, `CredWriteW`, `CredDeleteW`) and **additional current-user DPAPI** (`CryptProtectData/UnprotectData`, no machine-scope flag). DPAPI optional entropy is derived from an opaque per-test target. Account, channel and tenant are hashed with SHA-256 into a target name; the payload is DPAPI-encrypted with that exact target as optional entropy. Metadata and fake secret are inside the DPAPI blob. Small, synthetic payloads only; over 512 bytes of fake plaintext are rejected (WinCred permits at most 2,560 bytes in the protected credential blob). No encrypted file backend, AEAD file code, legacy V1 secrets, production Signal state or TDLib database.

Each test uses its **own random-looking unique test namespace** and deletes only exact targets it created. Normal application code has no way to invoke successful operations. Windows Credential Manager/DPAPI protect at OS logon user boundary; a separate **same-user untrusted process** remains a future native-host/IPC security risk and cannot be considered resolved by WinCred/DPAPI alone. Never ship with `cfg(test)` pathways re-enabled, never add JS access to the native functions, never expose target/ref.

Temporary test-only interface: `Identity` (tenant, channel, account), `Fence` (sessionRevision, bindingRevision, accountRevocationEpoch), `Vault::store_fake/inspect/lease/rotate_fake/revoke`. `lease` returns an opaque `SecretLease` without any public plaintext accessor, only private tests can inspect it. Vault checks exact identity, fence and credential revision; expired and revoked records fail closed; revoked tombstones persist rather than silently deleting version. A new separate OS process reopens the same synthetic namespace for the integration test; a full Windows machine reboot has not been tested; all tests clean only their own fake record. At this stage there is no durable CAS across *independent processes*, no W44 epoch service, no authoritative W54 NativePrincipal and no source-security/LEGAL approval.

Run from this directory using `C:\Users\1\.cargo\bin\cargo.exe test --locked --offline`. CI must not run with privileged real provider credentials or restore historical records. Test verification of a second actual Windows SID requires a deliberately provisioned isolated second OS account; code only proves current-user WinCred/DPAPI operation today.
