## W54 implemented NATIVE-process-only source interface

apps/windows/src-tauri/src/native_profile.rs and existing official Tauri setup in main.rs:

- Windows token User SID and TokenStatistics (existing W54) bind the CURRENT process; new Windows SHGetKnownFolderPath FOLDERID_LocalAppData validates that the current Tauri app_local_data_dir() is beneath the CURRENT Windows OS user's local Known Folder. Parent folder must match the official app.config().identifier and end in /data. Browser-provided paths are never consulted.
- A nonsecret installation namespace generated by OS RNG (32 random bytes) is stored in the current user's app-local data file w54-native-binding.state. File contents: schema, install namespace, revocation generation; exclusive Windows file handle, sync, strict parser, unknown/empty/tampered state rejects. The namespace and generation are NOT credentials or security-capability tokens.
- Stable private principal_ref is SHA256(domain prefix + OS token SID bytes + install namespace), so same user plus same app installation retains identity across restart and cookie renewal. Stable installation_ref derives from saved install namespace. New boot gets a distinct random session_ref. Neither exposes raw SID or paths to JS. Another app installation gets distinct references. Different real Windows OS users have NOT been tested.
- Persistent revocation_generation increases on each native host startup, logout and app Exit. Startup after crash invalidates prior process generation. Internal SessionAuthority.native_active_revision() still checks current OS process and live TTL/revocation; NativeProfileAuthority.verify_for_native_owner() compares OS token, stable installation namespace, canonical data root, file generation and active session.
- NativeProfileEvidence provides internal principal_ref, installation_ref, session_ref, session_revision, revocation_generation and app_local_data_root. Struct is non-serializable, Debug redacted and not included in Tauri command handlers. Existing Tauri renderer command allowlist remains session_status / logout_session, with serverTrusted=false and canSend=false.

## Independent verification and unclosed limits

Actual Windows profile and process test, same-user child process epoch invalidation, stale/unknown file denial and OS knownfolder negative all belong in W54 Owner test record. Those do not prove a second Windows OS user, signed installer, or attacker same-SID process resistance.

LIMITATION: A file in the current user's AppData is not an authenticated cross-process attestation and is not tamperproof against an attacker running under the same Windows user. This file stores revocation state and stable identifiers only; it cannot approve pairing or serve as an authority source for W47. No secure cross-process channel implemented or approved in this W54 delta; no independent SEC signature can be self-issued.
