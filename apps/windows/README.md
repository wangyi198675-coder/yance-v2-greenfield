# Yance V2 · W54 isolated Windows native-session lab

Scope: **ONLY apps/windows/** of worktree `W54_WINDOWS_NATIVE_IPC_20261026`; no product backend, root config, provider account, login DB or W25 send. This is a minimal standalone Tauri 2 desktop shell, not an integrated Yance installer or authorized social identity.

## Reproduce on Windows
```powershell
cd apps/windows/src-tauri
cargo fmt --all -- --check
cargo test --offline --locked
cargo build --offline --locked
# Output: src-tauri/target/debug/yance-v2-native-session-lab.exe
cd ..
node --test test-nonauth.mjs
node generate-sbom.cjs
```
Tauri 2.12.0, tauri-build 2.7.0, Rust 1.99.1 pinned; transitive crates pinned by src-tauri/Cargo.lock. No production MSI/MSIX/signing or WebView2 provision/deployment performed. Windows icon generated by `src-tauri/generate-icon.cjs`.

## Implemented boundaries
- Rust checks **current Windows process** token SID, logon AuthenticationId, process ID. It does not accept actor/tenant from JS/headers.
- Native-only random per-start boot/session ID and single-use challenge, revision/rotate/revoke/expiry; no session ID or proof is Serializable or exposed by invoke.
- Two allowlisted Tauri app commands for bundled local main window: `session_status` (redacted) and `logout_session`. No remote URL capabilities; no sender/credential access.
- UI always shows `serverTrusted=false`, `canSend=false` and no connected accounts. Opening index.html in ordinary browser cannot mint OS session.
- W47 remains the sole HTTP Owner; its active 47182 no-auth endpoint is unmodified. W24 canonical identity/Consent, W44 durable Grant/STOP/Budget, W25 send/ACK and W26–W29 providers untouched.

## Explicit HOLD (not tested or not implemented)
Native private **cross-process** verified transport W54 → W47 is not in place. Thus W47 cannot consume native session; both `REAL_CONTACT` and `REAL_STOP` are still unauthorized and 401/403. Same-Windows-SID malicious native-process client must be tested when a private transport exists; current native proof is confined to process memory with no listener. No persistent monotonic revision store across *crash*, no external Session API, no app signature/installer security, no real social accounts or messages. Same-user process injection or OS-token theft remains outside this prototype's asserted protection. Independent SEC, QA, legal, official source-maintainer and GitHub ACL/signing approvals are pending.

Windows Rust tests are isolated verification of *internal* API. The Node HTTP tests use actual read-only W47 requests plus two browser-like isolated JS VM contexts; they are not two real browsers or installed app UAT. The host executable startup-and-clean-exit smoke is distinct from formal desktop visual tests.
